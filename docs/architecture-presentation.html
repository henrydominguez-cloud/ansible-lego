Extend the base

New brick / new service = one command

Add a technology (brick) 
copymake new-brick NAME=myapp
# scaffolds roles/components/myapp from skeletons/ — install|config|service, OS assert, tags
Add a deployable (service) 
copymake new-service NAME=my-api
# roles/services/my-api: meta (which bricks) + vars/ (identity) + defaults/ (per-env) + files/

Then point meta at your bricks, add a playbook + a host group. That's a new deployable.

Interactive · the one gotcha

Who sets the value? ⚖️

A brick's own defaults shadow a service's defaults/ during its run. Toggle layers — the highest enabled wins (like nginx_port).

Rule: service must-set knobs → the service's vars/ (or {{ knob | default(x) }} in the brick). Per-environment knobs → service defaults/ + real value in inventory.

Run it

Local lab, any architecture 🚀

copymake deps            # once: collections
make lab-up          # EL9/EL8 containers with systemd
make lab-run PB=alpha-hello   # 1 brick:  nginx            -> :8080
make lab-run PB=alpha-notes   # 2 bricks: nginx + postgres -> :8081 + a 'notes' DB

nginx & postgres are arch-native, so both examples install and run for real on Apple Silicon.
